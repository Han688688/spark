## 一、项目概述

### 1.1 项目背景

**角色**: AI4SE资深测试架构师（20年经验）

**核心问题**: 
- 开源三方件多（Spark、Kafka、HDFS、Hive等）
- 组件交互场景复杂
- 测试覆盖率低
- 场景遗漏导致问题流入下游

**目标**: 利用大模型构建数据驱动+多组件协同的自动化测试方案

### 1.2 方案演进

| 版本 | 方案名称 | 核心思路 | 状态 |
|------|---------|---------|------|
| v1.0 | API全覆盖方案 | 提取所有API，逐个生成测试用例 | ❌ 废弃（成本高） |
| v1.5 | Skill架构方案 | 5个Skill协作，知识图谱驱动 | ❌ 暂缓（复杂度高） |
| **v2.0** | **交互泛化方案** | **组件交互描述+种子用例→智能泛化** | ✅ 采用 |

### 1.3 v2.0方案核心特点

**核心理念**: 从"API全覆盖"转向"基于交互场景的智能泛化"

**优势对比**:

| 维度 | API全覆盖方案 | 交互泛化方案（v2.0） |
|------|--------------|---------------------|
| **覆盖范围** | 所有API（1000+） | 关键交互场景（10-50） |
| **生成质量** | 机械生成，质量一般 | 从种子学习，质量高 |
| **维护成本** | 高（用例数量大） | 低（用例精简） |
| **执行效率** | 低（全量执行慢） | 高（聚焦关键路径） |
| **实用性** | 理论覆盖，实际低效 | 经验驱动，实际高效 |

## 五、方案演进历程

### 5.1 方案对比

| 方案版本 | 方案名称 | 适用场景 | 优缺点 | 采用状态 |
|---------|---------|---------|--------|---------|
| **v1.0** | **API全覆盖方案** | 理论覆盖 | 优点：覆盖全面<br>缺点：成本高、维护难、实用性低 | ❌ 废弃 |
| **v1.5** | **Skill架构方案** | 知识图谱驱动 | 优点：理论完整<br>缺点：复杂度高、实施周期长 | ❌ 暂缓 |
| **v2.0** | **交互泛化方案** | 实用高效 | 优点：聚焦关键、质量高、成本低<br>缺点：不适用API全覆盖 | ✅ 采用 |

### 5.2 v1.0方案（API全覆盖）- 已废弃

**核心思路**:
- 提取所有组件API（Spark 160+、Kafka 668、HDFS 360）
- 为每个API生成测试用例
- 目标：100%API覆盖

**废弃原因**:
1. ❌ 成本高：1000+API → 10000+用例
2. ❌ 维护难：用例数量巨大，难以维护
3. ❌ 实用性低：机械生成，场景单一
4. ❌ 执行慢：全量执行耗时过长
5. ❌ 不聚焦：关键路径淹没在海量用例中

**完成成果**:
- ✅ API文档完整提取（Spark/Kafka/HDFS）
- ✅ API文档质量优化（示例、最佳实践）
- ⭐ 这些文档仍有价值，可作为参考

### 5.3 v1.5方案（Skill架构）- 暂缓

**核心思路**:
- 5个Skill协作（KnowledgeGraph、InteractionIdentifier、APIMatcher、ScenarioGenerator、Documentation）
- 知识图谱驱动（组件能力、协议、API、案例、配置）
- 自动推理交互关系

**暂缓原因**:
1. ❌ 复杂度高：5个Skill协作，逻辑复杂
2. ❌ 实施周期长：知识图谱构建耗时
3. ❌ 维护成本：知识图谱需要持续更新
4. ❌ 过度设计：对于当前需求过于复杂

**完成成果**:
- ✅ Skill架构设计文档
- ✅ 流程图和架构图
- ⭐ 架构设计有价值，未来可参考

### 5.4 v2.0方案（交互泛化）- 采用

**核心思路**:
- 输入：组件交互描述 + 种子用例
- 泛化：从种子学习模式，智能泛化
- 输出：高质量精简用例 + 自动化脚本

**采用原因**:
1. ✅ 实务高效：聚焦关键交互场景
2. ✅ 质量可控：从种子学习，生成质量高
3. ✅ 成本低：用例精简（10-50个）
4. ✅ 易维护：模板化、标准化
5. ✅ 易扩展：添加新场景只需增加种子

**适用场景**:
- ✅ 组件交互测试
- ✅ 数据流测试
- ✅ 边界值测试
- ✅ 异常处理测试
- ❌ API全覆盖测试（不适用）
- ❌ 性能基准测试（不适用）

## 七、使用指南

### 7.1 快速开始

**Step 1: 阅读文档**
```bash
cat hyx/TestCaseGenerationSkill/docs/USAGE.md
cat hyx/TestCaseGenerationSkill/examples/README.md
```

**Step 2: 准备交互描述**
```bash
# 参考模板
cat hyx/TestCaseGenerationSkill/templates/interaction_template.yaml

# 编写你的交互描述
vim my_interaction.yaml
```

**Step 3: 准备种子用例**
```bash
# 参考示例
cat hyx/TestCaseGenerationSkill/seed_cases/spark_kafka_hdfs/example_seed.yaml

# 编写你的种子用例
vim my_seed.yaml
```

**Step 4: 执行生成**
```bash
cd hyx/TestCaseGenerationSkill

python src/skill.py \
  --interaction my_interaction.yaml \
  --seed my_seed.yaml \
  --output output
```

**Step 5: 查看输出**
```bash
ls output/
# test_cases.json         # 测试用例
# test_script_0.py        # 自动化脚本
# coverage_analysis.yaml  # 覆盖分析
# generation_report.md    # 执行报告
```

### 7.2 配置说明

**生成限制配置** (`config/generation_limits.yaml`):

```yaml
quantity_limits:
  max_cases_per_scenario: 10  # 每场景最多10个用例
  min_cases_per_scenario: 3   # 每场景最少3个用例

priority_distribution:
  P0_ratio: 0.2  # 20%核心用例
  P1_ratio: 0.5  # 50%重要用例
  P2_ratio: 0.3  # 30%边界用例

coverage_dimensions:
  required:
    - normal_flow      # 必选：正常流程
    - error_handling   # 必选：异常处理
    - boundary_values  # 必选：边界值
```

### 7.3 输出解读

**test_cases.json**: 生成的测试用例列表
- case_id: 用例ID
- case_name: 用例名称
- priority: 优先级（P0/P1/P2）
- scenario: 场景信息
- test_steps: 测试步骤
- assertions: 验证点

**test_script_*.py**: pytest自动化脚本
- 测试类定义
- Setup Fixture
- 测试方法（正常/异常/边界）

**coverage_analysis.yaml**: 覆盖分析
- dimensions: 维度覆盖情况
- components: 组件覆盖情况
- overall_coverage: 总体覆盖率

**generation_report.md**: 执行报告
- 生成时间
- 用例数量
- 优先级分布
- 覆盖情况
- 质量指标
