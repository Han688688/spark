# 用例生成规则文档

**版本**: v3.0  
**定位**: 定义用例生成的数量、分布、策略规则

---

## 一、生成数量规则

### 1.1 总量控制

**规则**:
- **最少生成**: 3个用例
- **最多生成**: 10个用例
- **推荐数量**: 5-7个用例

**优先级分布**:
- **P0占比**: ≥50%（至少3个）
- **P1占比**: ≤30%（最多3个）
- **P2占比**: ≤20%（最多2个）

---

### 1.2 类型分布

**必选类型**（3种）:
1. **正常流程用例**: 至少1个，推荐2-3个
2. **异常处理用例**: 至少1个，推荐1-2个
3. **边界值用例**: 至少1个，推荐1-2个

**可选类型**（2种）:
4. **性能测试用例**: 可选，0-1个
5. **稳定性测试用例**: 可选，0-1个

---

## 二、正常流程生成规则

### 2.1 基础正常用例（必须生成）

**数量**: 1个  
**优先级**: P0  
**数据量**: 适中（100-1000条）  
**特点**: 
- 包含完整流程步骤
- 所有步骤成功执行
- 数据完整无丢失

---

### 2.2 变体正常用例（可选生成）

**数量**: 0-2个  
**优先级**: P1  
**变体策略**:

**数据量变体**:
- 小数据量变体：10条
- 大数据量变体：1000条

**数据格式变体**:
- JSON格式变体
- CSV格式变体
- Avro格式变体

**流程变体**:
- 并行处理变体
- 批量处理变体

---

## 三、异常处理生成规则

### 3.1 核心异常用例（必须生成）

**数量**: 1个  
**优先级**: P0  
**异常类型**:
- 组件故障（Kafka故障、Spark故障、HDFS故障）
- 网络故障（连接超时、网络中断）
- 数据异常（数据格式错误、数据缺失）

**策略**: 每个组件至少生成1个故障用例（最多2个组件）

---

### 3.2 边缘异常用例（可选生成）

**数量**: 0-1个  
**优先级**: P1  
**异常类型**:
- 配置异常
- 权限异常
- 资源异常

---

## 四、边界值生成规则

### 4.1 最小边界用例（必须生成）

**数量**: 1个  
**优先级**: P1  
**数据量**: 最小值（1条）  
**特点**: 验证最小数据量处理能力

---

### 4.2 最大边界用例（可选生成）

**数量**: 0-1个  
**优先级**: P1  
**数据量**: 最大值（10000条）  
**特点**: 验证最大数据量处理能力  
**注意**: 最少3个用例场景下，只需生成1个最小边界用例即可

---

## 五、生成策略

### 5.1 优先级策略

**策略**: 优先生成P0用例，再生成P1，最后P2

**顺序**:
```
Step 1: 生成正常流程用例（P0）
Step 2: 生成异常处理用例（P0）
Step 3: 生成边界值用例（P1）
Step 4: 检查总量，裁剪超量用例
```

---

### 5.2 裁剪策略

**规则**: 当生成用例数超过max（10个）时，按优先级裁剪

**裁剪顺序**:
```
优先保留P0 → 其次保留P1 → 最后裁剪P2
```

**示例**:
```
生成15个用例，超过max=10，裁剪规则：
- 保留所有P0用例（假设7个）
- 保留部分P1用例（最多3个）
- 裁剪所有P2用例（5个 → 0个）
```

## 六、生成模板

### 6.1 正常流程模板

```yaml
case_type: normal_flow
priority: P0
test_data:
  input:
    data_size: 100
    data_format: JSON
assertions:
  - assertion_type: count
    description: 验证数据数量
  - assertion_type: value
    description: 验证数据完整性
```

---

### 6.2 异常处理模板

```yaml
case_type: error_handling
priority: P0
scenario:
  error_type: component_failure
test_steps:
  - action: simulate_failure
    component: TargetComponent
  - action: trigger_process
    expected_result: exception
assertions:
  - assertion_type: exception
    description: 验证异常捕获
```

---

### 6.3 边界值模板

```yaml
case_type: boundary_values
priority: P1
test_data:
  input:
    data_size: 1 # 最小边界
assertions:
  - assertion_type: count
    description: 验证边界处理
```

## 七、种子泛化算法

AI从种子用例到新生成用例的变换规则。以下5条是必须执行的泛化策略：

### 7.1 步骤模板提取

**算法**: 从种子用例的test_steps提取action列表作为新用例的步骤模板。

**示例**:
```
种子步骤: [read_from_hdfs, process_data, produce_message]
提取模板: 新用例保留相同的action序列，替换数据参数
```

### 7.2 数据量替换

**算法**: 将种子test_data.input.data_size替换为边界值或变体值。

**替换表**:
```
种子值 → 替换值列表
100 → [1, 10, 100, 1000, 10000]（选取适当的边界和变体）
```

**规则**: 正常用例使用种子原始值或相近值；边界用例使用1（最小）或10000（最大）。

### 7.3 异常路径翻转

**算法**: 将种子正常流程翻转为异常路径。

**翻转规则**:
```
正常步骤 → 异常步骤
"read_from_hdfs" → "simulate_hdfs_failure" + "verify_retry"
"produce_message" → "simulate_kafka_failure" + "verify_exception"
```

**规则**: 选择flow中涉及的1个组件，将其正常action替换为故障模拟+异常验证。

### 7.4 组件替换泛化

**算法**: 将种子中的组件名替换为交互描述中的其他组件。

**规则**: 仅在交互描述包含多个同类组件时使用。例如Spark读HDFS → Spark读Hive。

### 7.5 验证点映射

**算法**: 从种子assertions提取验证模式，映射到新用例。

**映射规则**:
```
种子 assertion_type → 新用例 assertion_type
count → count（数据量变化时调整expected_value）
value → value（替换具体预期值）
exception → exception（异常用例必选）
function → function（验证功能执行）
```
