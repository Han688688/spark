## 核心方案：可扩展框架

### 架构设计

```
┌─────────────────────────────────────────────────┐
│         Plugin System (插件系统)                │
│  - 分析插件：代码/配置/API/文档                  │
│  - 生成插件：LLM/数据驱动/Mock                   │
└─────────────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│     Strategy Registry (策略注册表)              │
│  - interaction: 调用链/日志交互识别             │
│  - exception: 历史缺陷场景识别                  │
│  - performance: 性能场景识别                    │
│  - 可无限扩展新策略                             │
└─────────────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│      Workflow Engine (工作流引擎)               │
│  - 可自定义流程                                 │
│  - 可组合多个策略                               │
│  - 可配置参数（优先级、数量等）                  │
└─────────────────────────────────────────────────┘
```

### 交互场景识别方法

**多维度识别**：

| 维度 | 方法 | 提取内容 |
|------|------|----------|
| **调用链** | 静态代码分析 | ComponentA.method → ComponentB.method |
| **配置依赖** | 配置文件分析 | database.url → MySQL, api.endpoint → Service |
| **运行时日志** | 日志分析 | [Spark] calling Hive, ERROR: ComponentX timeout |
| **API文档** | Swagger分析 | /api/v1/users → UserService |

**场景生成矩阵**：

每个识别到的交互生成5类场景：

```
Interaction(Spark → Hive, interface=sql())

生成:
├── 正常交互：Spark SQL查询Hive
├── 异常交互：Hive不可用、网络超时
├── 边界交互：超大表、高频调用
├── 并发交互：多个作业并发查询
└── 版本兼容：不同版本组合测试
```

```yaml

workflows:
  my_custom:
    steps:
      - type: analyze
        plugin: static_code_analyzer
      - type: discover
        strategy_category: interaction

      - type: generate
        plugin: llm_generator
```

## 与原方案对比

### 原方案 (agent.py)

```
优点：
✓ 简单易用
✓ 单文件实现

缺点：
✗ 硬编码流程，扩展需改代码
✗ 交互识别只有基本能力
✗ 维护成本高
```

### 新方案 (framework.py)

```
优点：
✓ 插件化，添加能力无需改核心代码
✓ 多策略识别，不同维度识别交互
✓ 工作流编排，自定义流程
✓ 配置驱动，灵活调整
✓ 可跨项目复用

适合：
✓ 多组件交互复杂项目
✓ 需持续扩展能力
✓ 团队协作（每人贡献插件）
✓ 不同项目复用
```

## 总结

**核心价值**：

1. **可扩展** - 添加新能力只需写插件，不改核心代码
2. **多维度** - 从调用链、配置、日志、API多角度识别交互
3. **自动化** - AI生成测试，无需手工编写
4. **可复用** - 框架可用于任何项目

**适用场景**：

- ✓ 多三方件交互复杂的系统
- ✓ 需要持续扩展测试能力
- ✓ 团队协作共建测试库
- ✓ 不同项目复用框架
